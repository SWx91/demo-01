## Parent

Part of #3 (Sales and reporting).

## What to build

Make sale confirmation safe to retry. The confirm route takes a client-supplied idempotency key backed by a database unique constraint: resending the same request with the same key returns the original sale and deducts stock no further.

`Covers:` SAL-03 (duplicate confirmation never double-posts). AC-06.
`Demo:` staff_b01 confirms a sale, then resends the same request → the original sale is returned and stock is not deducted again
`Seams:` oRPC controller spec; Postgres integration spec

## Acceptance criteria

- [ ] Resending a confirmation with the same idempotency key returns the original sale and makes no further stock deduction (Postgres integration spec; fails today — no idempotency). [AC-06]
- [ ] A confirmation with a new idempotency key records a separate sale (oRPC controller spec; fails today). [SAL-03]
