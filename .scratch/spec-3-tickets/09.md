## Parent

Part of #3 (Sales and reporting).

## What to build

Provide a daily sales report filtered by date range and store, including only successfully confirmed sales, showing document count, units sold, and total sales amount. A reporting day follows the Asia/Bangkok boundary on the sale confirmation timestamp. When no records match, show zero totals and a clear empty-state message. Export the report as CSV with the same filters and permissions as the screen, Thai-safe. Store employees see their store only; managers see all.

`Covers:` RPT-01 (daily sales); RPT-04 (sales CSV); display rules. AC-08.
`Demo:` the daily report for B01 shows document count, units sold, and total; a day with no sales shows zero totals and an empty-state message; CSV exports open correctly in a Thai spreadsheet
`Seams:` oRPC controller spec; web component test

## Acceptance criteria

- [ ] The daily sales report filters by date range and store and includes only confirmed sales, showing document count, units sold, and total amount (oRPC controller spec; fails today — no report route).
- [ ] When no sales match the selected day, the report shows zero totals and an empty-state message (oRPC controller spec + web component test; fails today). [AC-08]
- [ ] The reporting day uses the Asia/Bangkok boundary on the confirmation timestamp (oRPC controller spec; fails today).
- [ ] CSV export applies the same filters and permissions as the screen and is Thai-safe with neutralized formula cells (oRPC controller spec; fails today). [RPT-04]
- [ ] A store employee's report is confined to their assigned store; a manager's spans all stores (oRPC controller spec; fails today).
