## Parent

Part of #1 (Master data and inventory foundation).

## What to build

Let any signed-in user search stock by SKU, product name, and store, showing current quantity and unit. A store employee sees only their assigned store; a manager (and administrator) sees all stores. Store scope comes from the signed-in identity, so a direct API request for another store returns nothing for it.

`Covers:` INV-01 (search); US-21 (store scoping)
`Demo:` search B01 stock and see current quantities; staff_b02 cannot see B01 stock
`Seams:` oRPC controller spec; web component test

## Acceptance criteria

- [ ] Stock search filters by SKU, product name, and store and returns current quantity and unit (oRPC controller spec; fails today — no stock search route).
- [ ] A store employee's search is confined to their assigned store, enforced at the API from identity, not from input (oRPC controller spec; fails today). [AC-04 shape]
- [ ] A manager's search spans all stores (oRPC controller spec; fails today).
- [ ] The search screen is paginated newest-first with loading/success/error states (web component test; fails today).
