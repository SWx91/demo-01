## Parent

Part of #1 (Master data and inventory foundation).

## What to build

Let an Administrator create and edit stores (code and name), and establish the list conventions every later list reuses: pagination, newest-first ordering, loading/success/error states on screen, and a Thai, actionable error format that never leaks stack traces. A non-administrator cannot manage stores, enforced at the API.

`Covers:` MD-03 (stores); US-20 (list conventions)
`Demo:` Admin adds B01 Central Store and B02 Riverside Store, sees them paginated newest-first; a non-admin API call is refused
`Seams:` oRPC controller spec; Zod schema spec; web component test

## Acceptance criteria

- [ ] An Administrator creates and edits a store with a code and name (oRPC controller spec; fails today — no store model/route).
- [ ] The store list is paginated and newest-first (oRPC controller spec + web component test; fails today).
- [ ] A non-administrator calling the store-management route directly is rejected with no data change (oRPC controller spec; fails today).
- [ ] The management screen shows loading, success, and error states, and errors are Thai and actionable without stack traces (web component test; fails today).
- [ ] Store code/name validation rejects empty values at the contract boundary (Zod schema spec; fails today).
