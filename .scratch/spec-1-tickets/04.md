## What to build

Let an Administrator maintain a supplier directory — code, name, and contact details — reusing the list conventions established for stores (pagination, newest-first, screen states, Thai errors). Each supplier is identified by a unique code.

`Covers:` MD-03 (suppliers)
`Demo:` Admin adds SUP01 SupplyOne Co Ltd with contact details; the supplier list paginates newest-first
`Seams:` oRPC controller spec; Zod schema spec; web component test

## Acceptance criteria

- [ ] An Administrator creates and edits a supplier with code, name, and contact details (oRPC controller spec; fails today — no supplier model/route).
- [ ] The supplier list is paginated and newest-first with loading/success/error states (oRPC controller spec + web component test; fails today).
- [ ] A non-administrator calling the supplier-management route directly is rejected with no data change (oRPC controller spec; fails today).
- [ ] Supplier code/name validation rejects empty values at the contract boundary (Zod schema spec; fails today).
