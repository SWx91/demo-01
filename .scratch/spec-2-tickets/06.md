## Parent

Part of #2 (Purchasing and goods receiving).

## What to build

Let a Store employee open an Approved or Partially Received order for their assigned store and see, per line, the ordered quantity, the quantity previously received, and the outstanding quantity. Orders for a store other than the employee's assigned store are not accessible, enforced at the API from identity.

`Covers:` GR-01 (eligible orders, per-line view); US-13; US-25
`Demo:` staff_b01 opens PO-DEMO-001 and sees ordered 20, received 0, outstanding 20; a staff_b02 API request for a B01 order is refused with no data change
`Seams:` oRPC controller spec; web component test

## Acceptance criteria

- [ ] A Store employee lists Approved and Partially Received orders for their assigned store only (oRPC controller spec; fails today — no receiving view).
- [ ] The receiving view shows ordered, previously received, and outstanding quantities per line (oRPC controller spec + web component test; fails today).
- [ ] A direct API request by a store employee to view/receive an order whose destination store is not theirs is rejected with no data change (oRPC controller spec; fails today). [AC-04]
- [ ] Orders that are Draft, Pending Approval, Rejected, or Cancelled do not appear in the receiving view (oRPC controller spec; fails today).
