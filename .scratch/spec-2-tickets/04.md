## Parent

Part of #2 (Purchasing and goods receiving).

## What to build

Let a Manager approve or reject a Pending Approval order with a reason. Approving freezes the lines, quantities, prices, and destination store. A rejected order stays viewable and resubmission requires a brand-new order, not a state change on the rejected one. A Purchasing officer cannot approve, enforced at the API. Creating or approving an order never changes stock.

`Covers:` PO-03 (approve/reject, freeze, resubmit = new); PO-02 (no stock change on approve); US-06
`Demo:` manager01 approves PO-DEMO-001 and it becomes Approved; buyer01's direct approve call is refused; the approved order can no longer be edited
`Seams:` oRPC controller spec

## Acceptance criteria

- [ ] A Manager approves a Pending Approval order with a reason, moving it to Approved (oRPC controller spec; fails today — no approve route).
- [ ] A Manager rejects a Pending Approval order with a reason; it becomes Rejected and remains viewable (oRPC controller spec; fails today).
- [ ] An Approved order's lines, quantities, prices, and destination store cannot be changed (oRPC controller spec; fails today).
- [ ] A Purchasing officer calling approve/reject directly is rejected with no status change (oRPC controller spec; fails today). [AC-04 shape]
- [ ] Approving does not create any stock movement or change any balance (oRPC controller spec; fails today). [PO-02]
