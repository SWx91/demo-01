## Parent

Part of #2 (Purchasing and goods receiving).

## What to build

Guarantee that two receipts confirmed at the same time against one order can never jointly exceed the ordered quantity. The cumulative-received check runs inside the transaction with a guarded update, so concurrent receiving requests are serialized at the database and the order total is never exceeded.

`Covers:` GR-05 (concurrent cap); US-22
`Demo:` two simultaneous receipts that would together exceed the order quantity — only the valid portion commits and the cumulative total never exceeds the ordered quantity
`Seams:` Postgres integration spec

## Acceptance criteria

- [ ] Two concurrent confirmations against the same order never produce a cumulative received quantity greater than the ordered quantity (Postgres integration spec; fails today — no concurrency guard).
- [ ] After concurrent receipts, the destination store's stock reflects exactly the quantity actually received, never more (Postgres integration spec; fails today).
