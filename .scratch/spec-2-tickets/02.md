## Parent

Part of #2 (Purchasing and goods receiving).

## What to build

Let a Purchasing officer create a draft purchase order — one supplier, one destination store, an expected receipt date, and at least one product line — and edit it while it is still Draft. Inactive products cannot be added to an order (reusing the shared inactive-product guard). The order list reuses the established list conventions (pagination, newest-first, screen states, Thai errors).

`Covers:` PO-01 (create and edit draft); US-07 (inactive product blocked)
`Demo:` buyer01 drafts an order for SUP01 to B01 with lines and edits it; adding an inactive product is refused
`Seams:` oRPC controller spec; web component test; Zod schema spec

## Acceptance criteria

- [ ] A Purchasing officer creates a Draft order with supplier, destination store, expected receipt date, and lines, and it persists (oRPC controller spec; fails today — no create route).
- [ ] A Draft order can be edited (lines added/changed) while in Draft (oRPC controller spec; fails today).
- [ ] Adding an inactive product to an order is rejected by the shared guard with a Thai actionable error (oRPC controller spec; fails today).
- [ ] The draft screen creates and edits an order and shows loading/success/error states, paginated newest-first (web component test; fails today).
